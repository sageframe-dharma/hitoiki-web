Documentation.

Hitoiki runs one shell command in a floating Mac panel. Enter the command, read its output, and dismiss the panel when you finish.

Installation

Hitoiki requires macOS 14 or later. It uses the shell and /usr/bin/ssh already installed on your Mac.

  1. Get the Hitoiki disk image from the download section. GitHub provides the free download; the optional Payhip purchase supports development.
  2. Open the .dmg and drag Hitoiki to Applications.
  3. Launch Hitoiki from Applications.
  4. Press Control-Command-Space to bring up the panel.

The app runs without a Dock icon. Opening Hitoiki again from Applications brings the panel forward if it is already running.

The default shortcut conflicts with macOS Character Viewer when that shortcut is enabled. Hitoiki reports an unavailable shortcut. Reassign the conflicting macOS shortcut, then reopen Hitoiki.

Your first command

  1. Invoke the panel and type uptime.
  2. Press Return. Output appears below the command as it runs.
  3. Read the exit status when the command finishes.
  4. Select text to copy, or use the Copy control to copy the retained output.
  5. Press Escape to dismiss the completed result.

Hitoiki runs one command at a time. A command can use pipes, quoting, redirection, and other syntax your shell understands.

uptime
df -h
printf 'hello\n' | tr '[:lower:]' '[:upper:]'

While a command runs, typed characters, Return, Delete, and pasted text go to that command. Full-screen controls and cursor-key interaction are outside Hitoiki's intended use.

Dismissal clears the displayed transcript. Copy output you want to keep before dismissing the panel.

Shell and environment

Each command runs in a new, non-interactive shell process. Hitoiki captures the environment from your login shell when the app starts, including exported variables such as PATH.

Interactive aliases and functions are not available. Use the real command, an executable script, or an SSH host alias defined in ~/.ssh/config.

Commands start in your home directory by default. To work elsewhere, include the directory change and command in the same line:

cd "$HOME/Projects/example" && git status --short

A cd or variable assignment does not change the next command's shell. File changes and other effects of a command still persist.

If an installed tool is missing from PATH, restart Hitoiki after updating your login-shell environment, or use the tool's full path.

How execution works

The shell runs inside a pseudoterminal (PTY), the operating-system interface that provides terminal input and output to a process. Hitoiki forwards keystrokes to the process and renders the bytes it sends back. This is what allows ordinary SSH and sudo prompts to work.

SSH commands

Enter the complete SSH command, including the destination and the command to run there. Your shell resolves ssh through its captured PATH, using that client's configuration, keys, known hosts, and SSH agent.

ssh server 'uptime'
ssh server 'df -h'
ssh user@server 'uname -a'

A host name such as server can be a normal network name or an alias in ~/.ssh/config. Hitoiki has no separate host list, connection credentials, or SSH configuration to maintain.

To select the SSH client bundled with macOS explicitly, enter /usr/bin/ssh instead of ssh.

Quote the remote command so your local shell does not expand it first. These single quotes make $HOME refer to the remote account:

ssh server 'ls -la "$HOME"'

Use a terminal for a persistent remote shell, tmux session, or full-screen remote application.

Sudo and password input

Local commands can request sudo in the usual way. Remote sudo often needs an allocated terminal; request one with ssh -tt:

ssh -tt server 'sudo systemctl status nginx --no-pager'

When the running command asks for a password, type or paste it and press Return. Input goes directly to the running process. Normal SSH and sudo password prompts disable terminal echo, so no password characters or placeholder dots appear in the transcript.

Hitoiki does not infer password prompts from their text or open a separate password field. A program that deliberately echoes input can display that input; its terminal behavior determines what comes back.

Retry with a remote terminal

If a simple SSH command fails with sudo's message that a terminal is required to read the password, Hitoiki offers Retry with -tt. Accepting the offer reruns the command with a remote terminal requested.

The retry is offered for commands beginning with ssh when a terminal option is not already present. For more complex shell expressions, enter -tt yourself where appropriate.

Sudo's policy, password requirements, and credential timeout belong to the machine running sudo. Hitoiki does not change that configuration.

Output, exit status, and copying

Standard output and standard error share the terminal transcript. Text appears as it arrives, with basic terminal colors and carriage-return updates such as progress counters.

The exit status follows completion. Exit 0 ordinarily means success; a nonzero exit is the command's reported failure. A signal status means the process was terminated by a signal.

Use text selection and Command-C, or the Copy control. With no selection, Copy uses the retained transcript. Copied output is plain text.

The retained transcript is bounded to 10,000 completed lines and 10 MiB of output, with a 1 MiB limit for a single line in progress. Old content is dropped as limits are reached. Redirect output to a file when you need a complete record:

ssh server 'journalctl -u nginx --no-pager' > "$HOME/nginx.log"

Hitoiki renders command output rather than a complete terminal screen. Use a terminal for cursor-addressed interfaces and full-screen programs.

Stopping commands

Stop or Control-C first sends SIGINT, the normal interrupt signal, to the local process group. A second Stop sends SIGKILL, which forces that group to terminate.

After Stop, Hitoiki stops drawing further output from that run. Quitting the app also terminates its owned local command.

Interrupting the local SSH process does not guarantee that the remote command stops. In particular, a remote command run without an allocated terminal can continue after SSH disconnects. Check the remote host when cancellation consequences matter.

Stopping a command does not undo changes it has already made.

Open in Terminal

After completion, Open in Terminal opens a terminal at the command's working directory. Terminal.app is the default.

It opens a new terminal for further work. It does not rerun the command or transfer the existing transcript into the terminal.

Working with a coding agent

Hitoiki accepts command text from any source. When an agent gives you a command requiring access you want to keep under your own control, run it yourself:

  1. Ask for the command and the machine and directory where it should run.
  2. Copy it into Hitoiki and review the command, host, and paths.
  3. Press Return and enter any required password yourself.
  4. Copy the relevant output back to the conversation.

You can keep the agent's permissions restricted while doing this. Hitoiki does not connect to the agent, grant it privileges, inspect its command, or enforce its permission settings.

Privacy and permissions

Hitoiki has no account or telemetry. Transcripts stay in memory; interactive responses are forwarded to the command rather than saved as a separate input record. Your Mac's clipboard contains text you copy.

Commands execute with your account's normal permissions. Sudo can elevate privileges according to local or remote policy. Hitoiki does not sandbox commands or make destructive commands harmless.

The command itself can read files, write files, contact remote services, print sensitive values, or produce logs. SSH host checks, authentication, and key handling remain the installed SSH client's responsibility.

Troubleshooting

The shortcut opens Character Viewer or does nothing

Another app or macOS may own Control-Command-Space. Check Keyboard Shortcuts in System Settings, reassign the conflicting shortcut, and reopen Hitoiki. Opening Hitoiki from Applications brings the panel forward while the app is running.

A command is not found

Use the executable's full path and check your exported PATH. Interactive aliases and functions are not loaded. Restart Hitoiki to capture changes to the login-shell environment.

SSH cannot connect or authentication fails

Check the same host and SSH command in a terminal. Run command -v ssh in both places to confirm which client your shell finds. Verify network reachability, host configuration, keys, and agent access with that client.

Sudo says it needs a terminal

Accept the offered Retry, or add -tt to the SSH command. Type the password when the remote command requests it.

The first command takes a few seconds to start

The first command waits for the login-shell environment capture. Shell startup files can delay it. If capture fails or times out, Hitoiki reports the failure and uses the app's existing environment.

Output is incomplete or a program looks wrong

Retained output has limits, and full terminal emulation is outside Hitoiki's scope. Save large output to a file or use a terminal for full-screen programs.

A stopped SSH command is still running remotely

Check the process on the remote host and stop it there if needed. Stopping the local SSH process cannot guarantee remote cleanup.

Building from source

The app is written in Swift 6, uses Swift Package Manager, and has no third-party package dependencies. Building requires macOS and a Swift 6 toolchain.

From a checkout of the application repository:

swift build
swift test

The repository's README contains the current development and packaging instructions. The application source is licensed under MIT.
