Use the SSH setup
you already have.

Hitoiki runs /usr/bin/ssh with your existing ~/.ssh/config, host aliases, keys, and SSH agent. Type the complete command, just as you would in a terminal.

ssh server 'df -h' ssh -tt server 'sudo systemctl status nginx --no-pager'

Password prompts work in the panel. Input is forwarded to the running command, and password entry respects terminal echo settings. If remote sudo needs a terminal, Hitoiki offers to retry with -tt.

Your agent gives you
a command to run.

Keep your coding agent's permissions restricted. When a command needs access to your Mac or a remote host, run it yourself in Hitoiki.

  1. Copy the command from the conversation.
  2. Paste it into Hitoiki, review it, and press Return.
  3. Copy the result back to your agent.

This works with any agent that gives you command text, including commands using SSH or sudo. You choose what runs and enter any required password yourself.

A few details.

Output and input

Output streams as the command runs, with color, text selection, and copying. Keyboard input goes to the running command. Stop interrupts it; a second Stop force-terminates the local process group.

Local operation

The app does not collect telemetry or require an account. Transcripts stay in memory. Commands you run can make their own network requests.

Shell behavior and limits

Commands use the environment captured from your login shell. Interactive shell aliases and functions are not available. Output retention is bounded.

Use a terminal for full-screen applications such as Vim, htop, or tmux, and for persistent sessions. Interrupting SSH without an allocated remote terminal can leave the remote command running.

Hitoiki runs commands with your account's permissions. It does not inspect commands, enforce agent permissions, or sandbox execution.
